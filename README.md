# PureFox

**Сетевой аудио-плеер (endpoint) на Luckfox Pico Max / Ultra с поддержкой внешних клоков**

> Это форк [ppy2/PureFox_v2](https://github.com/ppy2/PureFox_v2) (ветка `MAX_6.X`). В нём оставлены только плееры NAA, Scream, APScream, APrender (UPnP) и [Яндекс Музыка](#яндекс-музыка), вывод звука сделан bit-perfect, а ядро Linux можно выбрать: 6.1 или 5.10. На вкладке [«Твики»](#вкладка-твики) веб-интерфейса задаются частота процессора, сила выходов I2S и периоды DMA. Подробнее — в разделе [Изменения в этом форке](#изменения-в-этом-форке).


## О проекте

PureFox — прошивка для плат **Luckfox Pico** **Max** и **Ultra** на базе Rockchip RV1106, превращающая их в высококачественный сетевой аудио-транспорт с поддержкой:

#### Режим сетевого плеера

- Выход **I2S** (внешнее тактирование EXT / встроенный синтезатор PLL)

- Выход **USB**(UAC2)

#### Режим USB транспорта

- USB(UAC2) в I2S

#### Поддерживаемые стандарты audio

- Поддержка PCM 2ch до 768kHz или PCM 8ch до 192kHz

- Поддержка native DSD (64-512 по USB; до DSD1024 в режиме I2S при MCLK 1024x, со старым драйвером 1.6 — до DSD512)

## Изменения в этом форке

**Протестировано подключение по USB к Holo Audio Cyan 2 и по I2S в режиме PLL с КШ2, а также в режиме EXT с Holo Audio Cyan 2. Плееры Scream и APScream на всех версия ядра линукс**

По сравнению с исходным проектом [ppy2/PureFox_v2](https://github.com/ppy2/PureFox_v2):

### Звук

- **Bit-perfect вывод.** Из драйвера I2S убрана программная регулировка громкости — PCM приходит на ЦАП без изменений. Mute сохранён (GPIO mute, автоматический mute, контрол «PCM Playback Switch»). Удалены ползунок громкости в веб-интерфейсе и поддержка энкодера громкости.
- **DSD1024 по I2S** при множителе MCLK 1024x (45.1584 / 49.152 МГц). В режиме USB to I2S максимум остаётся DSD512.
- **Быстрый путь DSD** в драйвере I2S: перестановка слов DSD выполняется в кэшируемом буфере, поэтому некэшируемый DMA-буфер записывается один раз.

### Ядро Linux

На форуме сообщали, что прошивка 1.6 (ядро 5.10) звучит иначе, чем 2.8 (ядро 6.1). Чтобы это можно было сравнить, в прошивке есть три варианта ядра:

| Вариант | Ядро | Драйвер I2S | DSD по I2S | USB to I2S |
| ------- | ---- | ----------- | ---------- | ---------- |
| **6.1** (по умолчанию) | 6.1.118 | этого форка | до DSD1024 | да |
| **5.10** | 5.10.160, ядро и конфигурация PureFox 1.x | этого форка | до DSD1024 | нет |
| **5.10 (old drv)** | 5.10.160-pf16, то же ядро | из PureFox 1.6, с его device tree и настройкой тактирования | до DSD512 | нет |

- **6.1 и 5.10** работают с одним и тем же драйвером I2S (bit-perfect, те же настройки I2S), поэтому они отличаются только ядром и, по умолчанию, частотой процессора (ниже).
- **5.10 и 5.10 (old drv)** отличаются только драйвером I2S и device tree. В старом драйвере есть программная регулировка громкости; она стоит на 100 и из веб-интерфейса не меняется, а при 100 PCM передаётся без изменений.
- **Переключение.** Переключатель «Ядро 6.1 | 5.10 | 5.10 (old drv)» на вкладке **Твики** записывает выбранное ядро и device tree текущего режима I2S в загрузочный раздел, проверяет запись и перезагружает плату. Во время записи не отключайте питание; если запись не удалась, повторите её или перепрошейте плату через RV1106_Toolkit. Из консоли: `/opt/kernel.sh 6.1`, `/opt/kernel.sh 5.10` или `/opt/kernel.sh 1.6` (5.10 со старым драйвером), затем `reboot`; `/opt/kernel.sh` без параметров показывает текущее и выбранное ядро.
- **Частота процессора.** По умолчанию 5.10 держит процессор на 1608 МГц (governor performance), а 6.1 остаётся на 1104 МГц, выставленных загрузчиком. На вкладке **Твики** можно задать одну частоту для обоих.
- **С ядром 5.10** (с любым драйвером) USB-порт работает только в режиме хоста: выход на USB-ЦАП есть, режим USB to I2S недоступен.
- Выбор ядра сохраняется при онлайн-обновлении.

### Вкладка «Твики»

Вторая вкладка веб-интерфейса. На ней переключатель ядра, под предупреждением — что работает с выбранным ядром (DSD1024, USB to I2S), и настройки, которые не меняют аудиоданные, но делают плату электрически тише во время воспроизведения. Они применяются сразу, сохраняются после перезагрузки и онлайн-обновления (`/etc/lownoise.conf`) а значения по умолчанию оставляют плату как была. Сравнивайте их на слух, по одной.

| Настройка | По умолчанию | Что делает |
| --------- | ------------ | ---------- |
| **Частота процессора** | 1608 МГц на 5.10, 1104 МГц на 6.1 | Ограничивает частоту процессора (408–1608 МГц): меньше ток и ниже напряжение ядра. Воспроизведение почти не нагружает процессор; после снижения проверьте DSD512/1024 и 768 кГц на выпадения. |
| **Сила выходов I2S** | уровень 2 | Сила выходов SCLK, LRCK и данных, 0–7. Ниже — фронты медленнее, меньше звона и помех по земле; выше — для длинных проводов. |
| **Сила выхода MCLK** | уровень 3 | То же для выхода MCLK. В режиме EXT не действует: там MCLK — вход. |
| **Периодов DMA на буфер** | 16 | Драйвер делит буфер ALSA минимум на 16 периодов, по прерыванию на каждый. 8, 4 или 2 дают меньше периодов, они длиннее. Действует со следующего запуска воспроизведения. |
| **Ресемплинг Scream** | Вкл | Выкл: ALSA не пересчитывает частоту, которую выход I2S не поддерживает; Scream выдаёт ошибку. |

Из консоли: `/opt/lownoise.sh set KEY VALUE`, ключи описаны в скрипте.

### Плееры

- **Остались только NAA (HQPlayer), Scream, APScream и APrender (UPnP).** Удалены Roon Ready, Squeezelite, AirPlay (shairport-sync), MPD/upmpdcli (MPD вернулся только для [Яндекс Музыки](#яндекс-музыка)), APlayer, Spotify Connect, Qobuz Connect, Tidal Connect вместе с библиотеками, которые нужны были только им. Образ корневой файловой системы уменьшился примерно с 39 до 26 МБ (с тремя ядрами для [выбора ядра](#ядро-linux) — около 36 МБ; Яндекс Музыка с MPD добавляет ещё около 1 МБ).
- **Scream рядом с APScream.** Кроме закрытого приёмника APScream есть открытый приёмник [Scream](https://github.com/duncanthrax/scream) 3.6 (вывод через ALSA). Для него на Windows нужен стандартный драйвер Scream; ASIO-отправитель APScream в режиме AP или TCP он не принимает. На странице настроек задаются режим (multicast/unicast), multicast-группа, порт, сетевой интерфейс, задержка и устройство ALSA. Scream может позволить ALSA пересчитать частоту, которую выход I2S не поддерживает; переключатель **Ресемплинг Scream** на вкладке [«Твики»](#вкладка-твики) это отключает.
- **APScream** — приёмник [Album Player](https://albumplayer.ru) последней версии 2.9 для ASIO-драйвера asioscream (native DSD, UDP или TCP, порт 4011). На странице настроек задаются все параметры его `config.txt`: режимы AP, TCP и MMAP, порт, буфер ALSA, предзагрузка, задержка, ядро и приоритет процесса. По умолчанию буфер ALSA — 16384 кадра, предзагрузка — 20000, поэтому воспроизведение начинается примерно через полсекунды на 44,1 кГц; со штатными 100000 приёмника — около 2 с. Предзагрузка должна быть больше буфера (драйвер округляет его до целого числа периодов, 16384 становится 16400), иначе APScream ничего не играет.
- **NAA**: обновлён `networkaudiod`; имя в HQPlayer уникально для каждой платы (имя хоста плюс последние шесть шестнадцатеричных цифр MAC-адреса).
- **Яндекс Музыка** (перенесена из [DigiFox](https://github.com/DrModd/DigiFox)): играет через минимальный MPD, подробнее — [ниже](#яндекс-музыка).
- **Выбранный плеер сохраняется при отключении питания**: выбор сразу записывается во флеш-память.

### Прошивка и обновления

- **Релизы на GitHub.** Сборки прошивки публикуются как [релизы GitHub](https://github.com/fkrutko/PureFox_v2/releases) этого репозитория с номером `2.8.<число коммитов>` (например, 2.8.166).
- **Онлайн-обновление с GitHub.** Кнопка с номером версии в веб-интерфейсе скачивает последний релиз по HTTPS с проверкой сертификата (curl), проверяет контрольные суммы SHA-256 и устанавливает его поверх работающей системы, сохраняя настройки пользователя (выход, настройки I2S и Scream, пароль и т. д.). Прошивается выбранное ядро и только если оно изменилось; выбор ядра сохраняется. Файлы с luckfox.puredsd.ru больше не загружаются.
- **Возврат на ppy.** Кнопка **«Вернуться на ppy»** внизу вкладки [«Твики»](#вкладка-твики) заменяет эту прошивку последней сборкой ppy2 тем же способом, что и её онлайн-обновление (`/opt/to_ppy.sh`: rsync с luckfox.puredsd.ru, затем прошиваются загрузочные разделы), и перезагружает плату. Настройки сбрасываются на значения ppy2; выбранный плеер сохраняется (Scream становится APScream). Вернуться на этот форк можно из консоли, см. [Установка из консоли](#установка-из-консоли).

### Сборка

- `./release.sh` собирает текущий коммит локально и публикует его как последний релиз на GitHub (нужен `gh`). `./build.sh` только собирает.
- Собираются три ядра: 6.1 (основное, в `boot.img`) и два варианта 5.10 (пакеты `linux510` и `linux510-pf16`); их zImage и device tree лежат в `/data/boot/<вариант>/`.
- Сборка работает на хостах с GCC 15 (например, Fedora 43); Buildroot использует ccache.

### Скачивание

Последняя прошивка этого форка — на [странице релизов](https://github.com/fkrutko/PureFox_v2/releases/latest): `PureFox-<версия>.zip` — образ для прошивки через USB.

### Установка (через USB)

1. Установите драйверы с [Luckfox Wiki](https://wiki.luckfox.com/Luckfox-Pico-RV1106/Downloads)
2. Запустите [RV1106_Toolkit.exe](https://mega.nz/file/ndFiCATS#CG5lF0Nz7JWhmoyrECxeIQDIw3iS5Lv3PZq-MIzJa9c) от имени администратора, выберите **rv1106**
3. Зажмите кнопку **BOOT** на плате и подключите USB
4. Дождитесь появления **Maskrom** в программе
5. Распакуйте архив прошивки, затем выберите Download → USB → Search Path → папка с прошивкой
6. Отметьте все файлы и нажмите **Download**
7. После **Download done** подождите 1 минуту, затем отключите плату

### Установка из консоли

Плату с прошивкой ppy2 или более старой сборкой этого форка можно обновить по сети, без USB. Зайдите на плату по SSH (`root` / `purefox`) и выполните:

```
wget -O /opt/update.sh https://raw.githubusercontent.com/fkrutko/PureFox_v2/MAX_6.X/ext_tree/board/luckfox/rootfs_overlay/opt/update.sh && chmod 755 /opt/update.sh && /opt/update.sh
```

Команда заменяет `/opt/update.sh` скриптом онлайн-обновления этого форка и запускает его: скрипт скачивает последний релиз с GitHub, проверяет контрольные суммы, устанавливает его поверх системы и перезагружает плату. Выбранный плеер, выход и пароль сохраняются. В прошивке ppy2 нет curl, поэтому при этой первой загрузке сертификат сервера не проверяется; дальнейшие обновления идут через curl с проверкой. U-Boot остаётся от прежней прошивки, с ним всё работает.

Не копируйте `update.sh` с Windows: из-за переводов строк Windows оболочка сообщает, что файл не найден.

## Режимы работы

### I2S

- **EXT** — внешнее тактирование от мастер-клока
- **PLL** — синтезатор частоты RV1106. Качество внутреннего PLL на удивление очень высокое. По многим субъективным тестам аудио экспертов звучание внутреннего PLL не уступает звучанию дорогих внешних генераторов.

<img title="" src="images/2026-05-24-10-02-10-image.png" alt="" width="389">

Настройки меню I2S задаются в веб-интерфейсе (страница «Настройки I2S») и позволяют сконфигурировать I2S-выход под конкретный ЦАП:

- **Mode (Режим)** — `PLL` / `EXT`:
  - `PLL` — тактирование от внутреннего синтезатора RV1106 (MCLK работает как **OUTPUT**).
  - `EXT` — внешнее тактирование от мастер-клока (MCLK работает как **INPUT**).
- **Output Mode (Вариант выхода)** — `STD` / `8CH` / `L/R` / `±L/±R`:
  - `STD` — стандартный 2-канальный выход.
  - `8CH` — 8-канальный режим (PCM до 192 kHz).
  - `L/R` — режим дуал-моно.
  - `±L/±R` — дуал-моно с балансным выходом.
- **MCLK** — `512` / `1024` (коэффициент умножения мастер-клока).
- **PCM Swap** — `OFF` / `ON` — инверсия порядка каналов для PCM.
- **DSD Swap** — `OFF` / `ON` — инверсия физических каналов для DSD.
- **44/48 Swap** — `OFF` / `ON` — смена порядка частотных доменов (44.1 / 48 кГц).

> **Внимание:** выход MCLK в режимах PLL и EXT имеет разные настройки (OUTPUT/INPUT), а изменение любых настроек I2S вступает в силу только после **перезагрузки устройства**.


### USB (UAC2 Gadget)

- PureCore UAC2 — эмуляция USB Audio Class 2
- Поддержка PCM 2ch до 768kHz
- Поддержка DSD (DoP и Native через Alt-Setting 2)
- Режим **USB to I2S** — USB вход → I2S выход (только с ядром 6.1)
- Для поддержки native DSD и ASIO требуются проприетарные драйвера. Для тестирования предоставляются по запросу. Ведётся работа над собственными драйверами ASIO.  

### Переключение выходов

Через веб-интерфейс: тогл **I2S ↔ USB**

### Яндекс Музыка

Перенесена из [DigiFox](https://github.com/DrModd/DigiFox) (там она сделана по мотивам плагина для Volumio [achechulin/volumio-plugins-sources](https://github.com/achechulin/volumio-plugins-sources/tree/master/yandex_music)). Node.js и веб-страницы нет: с Яндексом общается небольшая служба на C, а управляет ей по сети приложение на компьютере.

- **Кнопка «Яндекс Музыка»** среди плееров включает MPD. Если активен другой плеер, запуск трека из приложения тоже включает MPD.
- **MPD** собран минимально: декодеры FLAC и MP3, вход curl, вывод ALSA на выход из `/etc/asound.conf` без программной громкости, без базы музыки, upmpdcli и avahi. Порт 6600 открыт в сети, MPD-клиенты тоже видят очередь.
- **`ymusicd`** (C, libcurl + OpenSSL, `ext_tree/package/ymusic`, служба `S96ymusicd`, работает всегда) слушает порт 6601:
  - JSON API для приложения, см. ниже;
  - `/track/<id>.flac?a=<альбом>` (только с самой платы) — поток трека для MPD: ссылка из `get-file-info` (подпись HMAC-SHA256), транспорт `encraw` расшифровывается на лету (AES-128-CTR), работает перемотка (Range), обрыв CDN докачивается с того же места;
  - «Моя волна»: на старте каждого трека — отзыв `trackStarted`, когда в очереди MPD остаётся меньше 3 треков — следующая партия.
- **Вход:** открыть в браузере ссылку `oauth` из `/status`, войти и отправить адрес страницы, на которую попали (с `access_token=…`), в `POST /login`. Пароль на плату не передаётся; токен хранится в `/var/lib/ymusic/token` и переживает онлайн-обновление.
- **Качество:** Lossless FLAC (если у трека есть, иначе MP3 320), MP3 320 или MP3 обычное (`/var/lib/ymusic/quality`). Нужна подписка Яндекс Плюс.
- Журнал ошибок — `/tmp/ymusicd.log`. Подробный журнал: `/etc/init.d/S96ymusicd stop; ymusicd -v`.

#### API Яндекс Музыки

`http://<плата>:6601/…`. Параметры — в строке запроса или в теле POST-формы (`application/x-www-form-urlencoded`). Ответ всегда JSON с `"ok": true`; при ошибке `"ok": false` и `"msg"` с кодом HTTP 4xx/5xx. Обложки — ссылки `https://` 400×400, длительности — в секундах. `GET /` — список адресов. Авторизации нет, как и у остальных сетевых служб платы.

| Запрос | Что делает |
|---|---|
| `GET /status` | версия, `token`, `login`, `plus`, `quality`, `oauth` (ссылка для входа) |
| `POST /login` `token=` | вход: `access_token` или весь адрес страницы после входа |
| `POST /logout` | удалить токен |
| `POST /quality` `q=lossless\|hq\|nq` | качество следующих треков |
| `GET /home` | `playlists` (свои), `personal` («Для вас»), `stations` (`seed`, `name`, `cover`, `color`) |
| `GET /likes` | «Мне нравится» |
| `GET /search?q=` | `tracks`, `albums`, `artists`, `playlists` |
| `GET /album?id=` · `/artist?id=` · `/playlist?uid=&kind=` | подробности с `tracks`; у альбома и исполнителя ещё `seed` для `/wave` |
| `POST /queue` `ids=id:альбом,…&start=N` | заменить очередь и играть с трека N; `append=1` — дописать в конец |
| `POST /wave` `seed=` | «Моя волна» (`user:onyourwave`, по умолчанию), станция, `album:<id>` или `artist:<id>` |
| `GET /queue?before=5&after=10` | `prev`, `current`, `next` вокруг текущего трека (до 100 в каждую сторону) |
| `GET /now` | текущий трек: `state`, `title`, `artist`, `album`, `id`, `a`, `cover`, `pos`, `dur`, `song`, `n`, `wave`, `codec`, `audio`, `kbps`, `svc` (активный плеер) |
| `/next` `/prev` `/toggle` `/pause` `/stop` `/play?pos=N` | управление (GET или POST); `play` без `pos` — продолжить |
| `POST /like` · `/dislike` `id=&a=` | в «Мне нравится»; dislike ещё и пропускает трек |

Трек — `{"id","a"(альбом),"title","artist","album","cover","dur","ok"}`; `ok: false` — играть нельзя, `/queue` его пропускает.

```sh
curl http://192.168.1.43:6601/now
curl -d seed=user:onyourwave http://192.168.1.43:6601/wave
curl http://192.168.1.43:6601/next
```
